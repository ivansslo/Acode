## 2025-02-14 - CodeMirror Mode Detection Bottleneck
**Learning:** In the CodeMirror 6 integration (`src/cm/modelist.ts`), retrieving a language mode via `getModeForPath` was sorting the entire list of registerable modes by specificity descending on every single call. This is an $O(M \log M)$ operation that copies arrays, splits strings, and calculates scores dynamically. Since mode registrations are largely static or modified only on plugin install/uninstall, we can lazily cache the sorted list of modes and pre-calculate specificity scores during constructor initialization to reduce lookup time to $O(M)$ (mostly $O(1)$) with zero sorting/allocation overhead.
**Action:** Always check if a highly repetitive lookup or search function (like file extension/mode resolvers) performs inline array duplication, sorting, or complex regex construction. Lazily cache the computed/sorted collection, pre-calculate immutable scoring properties, and invalidate the cache on mutation operations (like registrations/unregistrations).
